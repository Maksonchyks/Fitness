# Архітектура React-додатку (Clean Frontend Architecture)

Для масштабного проєкту на зразок застосунку для фітнесу/ліфтингу важливо дотримуватись чистої архітектури на фронтенді.

## Основні принципи

1. **Поділ на Розумні (Smart) та Дурні (Dumb) компоненти**:
   - **Smart Components (Контейнери)**: Знають про стан (State) та бізнес-логіку. Вони підтягують дані з API або Redux/Zustand і передають їх вниз.
   - **Dumb Components (Презентаційні)**: Відповідають лише за відображення (UI). Приймають дані через `props` та повідомляють про події через `callbacks` (наприклад, `onClick`). Це кнопки, картки тренувань, інпути.

2. **Feature-Sliced Design (Або модульна структура)**:
   Замість того, щоб групувати файли за типом (всі компоненти разом, всі хуки разом), групуйте їх за **фічами** (Features):
   ```text
   src/
    ├── features/
    │   ├── auth/ (компоненти, хуки, api, state для авторизації)
    │   ├── workouts/ (логіка тренувань, генерація програм)
    │   └── nutrition/
    ├── shared/ (спільні UI-елементи: кнопки, модалки)
    └── app/ (роутинг, глобальні провайдери)
   ```

3. **Custom Hooks для бізнес-логіки**:
   Виносьте логіку з компонентів у власні хуки. Наприклад, замість того, щоб писати логіку таймера відпочинку між підходами прямо в компоненті, створіть `useRestTimer()`.

4. **Типізація з TypeScript**:
   Завжди типізуйте `props`, `state` та відповіді від API. Це вбереже вас від багатьох помилок, особливо коли API (ваш .NET бекенд) буде розширюватись.
